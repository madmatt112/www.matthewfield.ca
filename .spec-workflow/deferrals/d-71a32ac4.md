## Context
Before this change the verifier counted an AC as covered whenever its tasks cell was non-empty, so `(18)`, `TBD`, `—`, and a typo like `tesk 18` all passed silently — the parser stripped parentheticals and found zero task numbers but still reported coverage. Tightening the rule to "at least one task number" required an escape hatch for genuine negative requirements verified by absence (profile-resume's R6.1: no `/resume` route is created). The sentinel is that hatch. The risk now inverts: a future spec author writing a legitimate no-coverage row in the old prose style will get an ORPHAN failure with no documentation explaining the sentinel. blog-core, the only other spec the verifier covers, has no such rows today.

## Decision Deferred
`scripts/verify-requirements-coverage.mjs` now requires every acceptance-criterion row to cite at least one task number, or to open its covering-tasks cell with an explicit `n/a` sentinel (`/^n\/a\b/i`). This convention was introduced in profile-resume's task 22 and applied to its AC 6.1, but it is not written down in any spec-authoring guidance.

## Revisit Criteria
Document the `n/a` sentinel wherever spec-authoring conventions live, alongside the matrix format itself, so the rule is discoverable before an author hits the failure rather than after.
