## Context
Buttondown documents every other variable used in the template (email.subject, email.publish_date, email.absolute_url, email.secondary_id, unsubscribe_url, manage_subscription_url, subscriber.email) but never names the body variable for custom templates — checked against docs.buttondown.com/template-variables, /using-templating, /api-emails-template and the Feb 2026 custom-templates blog post. No Buttondown account existed on the Professional plan at the time to read it empirically. The alternative considered was guessing from Buttondown's older template feature, which was rejected: presenting a guess as fact in a file someone will paste into production is worse than flagging it. The custom-css.css path reaches most of the design on the Basic plan, so this blocks nothing today.

## Decision Deferred
Which template variable injects the email body into a Buttondown custom HTML template. email/buttondown/template.html uses `{{ body }}` as a stand-in, and the newsletter name/description are hardcoded for the same reason. Also undecided: whether the full HTML template is worth the Professional plan at all.

## Revisit Criteria
Professional plan taken, OR a decision that the CSS-only path is sufficient and template.html should be deleted rather than maintained.
