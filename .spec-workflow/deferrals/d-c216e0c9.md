## Context
Found while fixing the same defect in src/lib/profile-json-ld.ts during profile-resume task 15. A raw 0x00 byte inside a template literal makes git classify the whole file as binary, so every diff on it renders as "Bin N -> M bytes" and is unreviewable. The byte renders as a space in an editor, so a future edit can silently corrupt the separator. tsc, eslint and prettier all miss it. profile-json-ld.ts was fixed in commit 7aa4bdb by replacing the raw byte with the escape sequence \\u0000, which is behaviourally identical. mail.ts was left alone because it is outside this spec's scope and touching it would put an unrelated file in the profile-resume PR.

## Decision Deferred
Did not apply the same raw-NUL-to-\\u0000 escape fix to src/lib/mail.ts:52, which still contains a raw 0x00 byte and is still binary to git.

## Revisit Criteria
Any change to src/lib/mail.ts, or the introduction of a lint/CI check for raw control characters in tracked text files.
