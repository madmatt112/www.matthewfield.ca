### INFO: Uses Promise.allSettled instead of design-pinned Promise.all
- **File:** /home/mcf/repo/matthew-field.ca/scripts/verify-deploy.mjs:69
- **Issue:** Task restriction and design snippet specify `Promise.all` for the three parallel checks; implementation uses `Promise.allSettled` (line 69). Functionally this is arguably an improvement — it surfaces every failing URL rather than short-circuiting on the first rejection, which aligns with the diagnostic-naming intent. Since `check()` resolves with a result record (never throws on HTTP non-200), `Promise.all` would not actually short-circuit in practice and the two would behave identically; `allSettled` only differs if `fetch` itself throws (network error) on multiple URLs. Noting as info; not a blocker.
- **Task Requirement:** Restriction: Three checks run in parallel via `Promise.all`.
