## Findings

### INFO [hygiene]: Timeout-path coupling to two abort windows is correct but fragile
- **File:** e2e/tests/contact-server-error.test.ts:99
- **Issue:** The 503 test relies on the route's server-side 9s abort (mail.ts TIMEOUT_MS=9000) firing BEFORE the form's client-side 12s abort (SUBMIT_TIMEOUT_MS=12_000). Verified correct today: 9s < 12s, so the server returns 503+Retry-After:60 and the client never aborts to a 'network' state. But this ordering is an undocumented invariant — if either constant changes the test would silently flip to the network-error path. A comment pinning the 9s<12s dependency would harden it.

### INFO: Mock /__mode status=503 branch is unexercised by this test
- **File:** e2e/tests/contact-server-error.test.ts:98
- **Issue:** mock-resend.mjs has a dedicated 503+retry-after branch (lines 61-69), but this test never uses status=503 (it correctly uses timeout, since a real upstream 503 maps to a client 502 via ResendError). Not a defect in the test — just noting the mock branch remains dead for the server-error suite; the chosen timeout approach is the right one for the genuine client-facing 503 path.
