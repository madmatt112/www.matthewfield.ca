## Findings

### WARNING: numberOfRuns: 1 reduces Lighthouse score reliability
- **File:** /home/mcf/repo/matthew-field.ca/lighthouserc.json:8
- **Issue:** `lighthouserc.json` sets `numberOfRuns: 1`. LHCI's default and recommended value is 3 runs (median is reported) to smooth out variance in performance scores. With a single run, scores will swing run-to-run, making the four-score PR comment noisy and weakening the merge-review signal that the task description calls out ('Matthew reviews scores in the PR comment as a merge-review check'). Recommend removing this override or setting to 3.
- **Task Requirement:** Req-NFR-Performance Lighthouse >= 90 clause

### WARNING [hygiene]: Local `pnpm lhci autorun` against localhost is not zero-config
- **File:** /home/mcf/repo/matthew-field.ca/lighthouserc.json:5
- **Issue:** Success criterion says 'running `pnpm lhci autorun` locally against http://localhost:3013 also succeeds'. The lighthouserc.json hardcodes `${LHCI_PREVIEW_URL}/profile` and `${LHCI_PREVIEW_URL}/contact`, so a local invocation requires the developer to export `LHCI_PREVIEW_URL=http://localhost:3013` first. Without that env var, LHCI will try to fetch `/profile` and `/contact` (unresolved interpolation) and fail. Consider documenting this in the README or providing a fallback default, e.g. `${LHCI_PREVIEW_URL:-http://localhost:3013}` if LHCI supports it.

### WARNING [hygiene]: Workflow lacks concurrency control for repeated preview deployments
- **File:** /home/mcf/repo/matthew-field.ca/.github/workflows/lhci.yml:6
- **Issue:** `.github/workflows/lhci.yml` has no `concurrency:` block. Vercel may emit multiple `deployment_status: success` events for the same PR (re-deploys, branch updates), spawning parallel LHCI runs that race to post the same GitHub status context. Add `concurrency: { group: lhci-${{ github.event.deployment.id || github.ref }}, cancel-in-progress: true }` to prevent stale runs from overwriting fresh ones.

### INFO [hygiene]: `actions/checkout@v4` on deployment_status checks out default branch, not PR HEAD
- **File:** /home/mcf/repo/matthew-field.ca/.github/workflows/lhci.yml:11
- **Issue:** On the `deployment_status` event, `actions/checkout@v4` with no `ref` checks out the repository's default branch (main), not the PR commit that triggered the Vercel preview. In practice this is fine because LHCI only needs `lighthouserc.json` and the URL list — both are stable across PRs once merged — but it means changes to lighthouserc.json in an open PR will not take effect until merged. Worth noting if the config is iterated on.

### INFO [hygiene]: `LHCI_GITHUB_APP_TOKEN` secret required for PR status posting
- **File:** /home/mcf/repo/matthew-field.ca/.github/workflows/lhci.yml:29
- **Issue:** The workflow passes `LHCI_GITHUB_APP_TOKEN` from `secrets.LHCI_GITHUB_APP_TOKEN`. If this secret is not configured (the LHCI GitHub App must be installed on the repo to obtain it), LHCI will still run and upload to temporary-public-storage but the per-category GitHub status context (and thus the four-score PR check the task asks for) will not be posted. Verify the secret is set in the repo, or document the install step.

Production deploys (environment `Production`) are excluded. Restriction 'do not run LHCI against localhost' is satisfied — the URL comes from `github.event.deployment_status.target_url`.
