=====================================================================
SPIKE FINDING (surfaced by the AC2 + shadcn-Button-typography tests)
=====================================================================
The playground.css @layer playground block cannot re-establish
non-custom-property typography on .playground-container because the
same rule block also applies `all: initial` unlayered. Unlayered rules
beat layered rules on the same element, so the `all: initial` reset
wins over the @layer playground declarations of font-family,
font-size, line-height, color, etc. Custom properties are NOT affected
— CSS `all` excludes custom properties by spec — which is why every
token-based assertion passes cleanly. Consequences:

  - .playground-container (and descendants by inheritance) renders
    with font-family at the CSS initial serif default ("Times New
    Roman" on Chromium's bundled font image in this CI env; other
    distros may report Liberation Serif / DejaVu Serif). The intended
    ui-sans-serif stack from @layer playground never materializes.
  - The container's own `color` computed value is CanvasText (which
    serializes to rgb(0, 0, 0) on Chromium's white canvas) from the
    reset, not from the @layer playground re-declaration.
  - Any shadcn component that relies on inherited typography from the
    container (e.g. the Button fixture's font-family) inherits the
    reset values, not the playground values.

Recommendation for task 14 / spec 8: move the typography
re-establishment out of @layer playground (either to an unlayered rule
on .playground-container with specificity high enough to beat the
reset, or to a second unlayered block declared after the reset). Keep
the custom-property re-establishment in @layer playground — it works
correctly there.

The `shadcn Button receives utility-class padding + records typography
regression` test asserts the computed font-family does NOT contain
`ui-sans-serif`. When the playground.css fix lands, that assertion
will flip (the playground stack will start appearing) and force the
test to be updated — that is the intended flip-from-broken-to-fixed
pattern.

the host's declared families appear proves the container's reset is

initial) appears instead of the intended playground ui-sans-serif
stack is the SPIKE FINDING surfaced above — not an AC2 failure.

Overlay containment matrix (from src/app/(playground)/spike/spike-overlays.tsx)
=====================================================================
Every shadcn/ui Content wrapper hardcodes its Portal and does not forward
a `container` prop, so the default behavior for Dialog, DropdownMenu,
Popover, Tooltip and Select is "portal escapes to document.body".

Tier 1 mitigation — exported Portal wrapper (spreads container prop):
  Dialog       → DialogPortal       (used in `Contained Dialog` branch is
                                     equivalent; we drop to the primitive
                                     for symmetry with Tier 2)
  DropdownMenu → DropdownMenuPortal

Tier 2 mitigation — drop to the underlying Radix primitive's Portal:
  Popover  → PopoverPrimitive.Portal     (no exported PopoverPortal)
  Tooltip  → TooltipPrimitive.Portal     (no exported TooltipPortal)
  Select   → SelectPrimitive.Portal      (no exported SelectPortal)

The `Contained Dialog` branch in the spike fixture proves the
container-prop pattern keeps the portal inside .playground-container.
Spec 8 (playground) will need to apply the appropriate tier to every
overlay-bearing playground item, or accept the document.body escape and
ensure those overlays inherit the host site's dark-mode tokens instead.

=====================================================================
Suggested graduated outcome (final call belongs to task 14)
=====================================================================
(b) Same-page CSS isolation is viable WITH restrictions:

  - Custom-property re-establishment inside @layer playground works as
    designed; the container's tokens override inherited :root.dark
    values and reach descendants via inheritance, var() consumption,
    and on shadcn components (Button fixture). R11 AC3 is satisfied at
    the primitive level for both div and Button component paths, and
    will be re-verified for the Tailwind utility path (bg-primary,
    text-primary-foreground) by task 15's @theme block.

  - Non-custom-property typography re-establishment (font-family,
    font-size, line-height, color) declared in @layer playground does
    NOT override the container's unlayered `all: initial` — the
    container and descendants render with browser-default typography.
    Follow-up task needs to move typography re-declarations out of the
    layer or use unlayered specificity to win against the reset. The
    shadcn Button typography assertion pins the current state so the
    fix or any future regression is immediately detectable.

  - Overlays portal to document.body by default; spec 8 must opt into
    Tier 1 / Tier 2 containment per overlay if the playground item
    needs its overlays to live inside the isolation boundary.

Outcome is (b), not (a), because the typography re-declaration bug is
a real gap in the isolation strategy even though the underlying AC2 /
AC4 goals (site globals don't leak, Tailwind utilities work) still
pass.

ThemeProvider integration follow-up (task 16)
=====================================================================
The dark-mode tests in playground-isolation.test.ts use
`applyDarkMode(page)`, which sets localStorage "theme"="dark" AND adds
the `.dark` class to <html> via an init script (pre-hydration). The
localStorage write is currently inert (no ThemeProvider in the build);
it becomes load-bearing when task 16 ships next-themes with
attribute="class" and defaultTheme="system".

When task 16 merges:
  1. Re-run the spike suite (`pnpm test:e2e e2e/tests/playground-
     isolation.test.ts`) to confirm the dark-mode assertions still hold
     against the new hydration path.
  2. If next-themes' mount race causes intermittent failures, either
     switch the manual `classList.add` out for `page.emulateMedia
     ({ colorScheme: "dark" })` combined with a deterministic wait on
     the rendered class, or add a fixture variant on
     (playground)/layout.tsx that does not mount ThemeProvider for
     spike tests.
  3. Update this file with the re-run reporter output so the dev vs.
     prod comparison remains evidenced.
