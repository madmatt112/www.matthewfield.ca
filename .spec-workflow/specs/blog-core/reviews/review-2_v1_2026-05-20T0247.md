## Findings

### INFO [hygiene]: Inconsistent optional chaining on properties read vs. write
- **File:** src/lib/build/rehype-absolutize-urls.ts:19
- **Issue:** `rewrite(node.properties?.href, baseUrl)` reads defensively, but the subsequent `node.properties.href = next` writes without optional chaining. In HAST, `Element.properties` is always present in practice (the type allows undefined but unified populates it), so this is fine, but the asymmetry suggests one of the two is wrong. Either drop the `?.` on the read (Element.properties is guaranteed in unified output) or guard the write. Suggest: `const props = node.properties ??= {}; const next = rewrite(props.href, baseUrl); if (next !== undefined) props.href = next;`.

### INFO: Functions are not exported as default and not re-exported via index
- **File:** src/lib/build/rehype-absolutize-urls.ts
- **Issue:** The task success criteria say `importable from velite.config.ts (relative path) and from src/lib/blog.test.ts (@/lib/build/...)`. Named exports work for both, so this passes. No barrel file exists; not required, just noting that if/when more helpers land here a `src/lib/build/index.ts` barrel would be nice. Non-blocking.

### INFO: Visitor visits all nodes (no type filter) — acceptable but slightly wasteful
- **File:** src/lib/build/word-count.ts:7
- **Issue:** `countWordsFromMdast` calls `visit(tree, (node) => ...)` without a test argument, traversing every node. Correctness is fine because only `text`/`image` push and `code`/`inlineCode`/`html` SKIP entire subtrees. No double-counting risk: `text` and `image` are leaf nodes in mdast (image has no children), so `toString` on them doesn't re-traverse already-visited subtrees. Could narrow with a tuple test (`['text','image','code','inlineCode','html']`) for a tiny perf bump, but current form is more readable.

### INFO: imageReference alt text is not counted
- **File:** src/lib/build/word-count.ts:11
- **Issue:** Only `image` (inline) nodes contribute alt text; `imageReference` (`![alt][id]` style) nodes are ignored. Spec phrasing says `mdast-util-to-string` with `includeImageAlt: true`, which by itself would include both when called on a tree root. Current implementation calls toString per-node and only on `image`, so reference-style images contribute zero words. Probably immaterial for this site, but worth knowing if the count ever looks low on posts using reference-style image syntax.

### INFO [hygiene]: URL.canParse requires Node 19+ — acceptable given engines.node >=24
- **File:** src/lib/build/rehype-absolutize-urls.ts:11
- **Issue:** `URL.canParse` is a Node 19.9+/20+ API. package.json now pins `engines.node: ">=24"`, so this is safe. Noted for completeness — if engines is ever loosened, this becomes a runtime hazard on older Node.
