## Findings

### WARNING: Case 11 allowlist filter is tautological — does not exercise filtering semantics
- **File:** src/lib/projects.test.ts:433
- **Issue:** In the second `it` of Case 11, `relativeFromRepo(CHOKEPOINT_PATH)` is asserted to be in PRODUCTION_ALLOWLIST on one line, then the very next expression `PRODUCTION_ALLOWLIST.includes(rel) ? [] : findings` will always evaluate to `[]` because the precondition was just asserted true. The `expect(violations).toEqual([])` therefore passes regardless of what `runChokepointScan` returned. A correct self-test would either (a) call a real allowlist-aware wrapper that filters findings, or (b) assert that scanning a non-allowlisted version of the same content does flag violations and the allowlisted path does not. As written, this case cannot fail in a meaningful way — mutating the production allowlist to remove `src/lib/projects.ts` would only fail the first `expect`, not exercise the filter.
- **Task Requirement:** 7.6.h / allowlist self-test
