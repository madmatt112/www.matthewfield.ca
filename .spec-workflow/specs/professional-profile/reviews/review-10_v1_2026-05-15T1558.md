### INFO: assertLogsScrubbed omits testId from scrubbed-fields list
- **File:** /home/mcf/repo/matthew-field.ca/src/lib/mail.test.ts:16
- **Issue:** The logging-discipline helper checks name/email/message/source but not testId. Req 3.10 says "no user-input fields in logs" — testId is internal (test-supplied via the route mock), so this is defensible, but ContactEmailInput exposes testId as a typed input field on the same shape. If a future regression in mail.ts logs the testId (e.g. for debugging the e2e mock path) the spy would not catch it. Trivial fix: add `if (input.testId) expect(haystack).not.toContain(input.testId);` to the helper and pass it through from the testId-forwarding tests.
- **Task Requirement:** Req 3.10 logging discipline

### INFO: env-tuple cache test only varies RESEND_BASE_URL, not RESEND_API_KEY
- **File:** /home/mcf/repo/matthew-field.ca/src/lib/mail.test.ts:142
- **Issue:** The cache key in mail.ts is `${apiKey} ${baseUrl}`, so a regression that hashed only the URL would also slip past this test. The task prompt explicitly names the BASE_URL variant ("env-tuple cache rebuilds when RESEND_BASE_URL changes") so this is in-scope as written and not a deviation, but a parallel assertion that flipping RESEND_API_KEY also rebuilds the client would fully lock the cache-key contract. Optional hardening, not a violation.
- **Task Requirement:** Design §Testing Strategy → mail.ts env-tuple cache

### INFO [hygiene]: Sanity-guard test relies on empty-string falsy fallback rather than asserting it
- **File:** /home/mcf/repo/matthew-field.ca/src/lib/mail.test.ts:163
- **Issue:** The sanity-guard test sets `RESEND_BASE_URL=""` and depends on mail.ts's `process.env.RESEND_BASE_URL || RESEND_DEFAULT_BASE_URL` to coerce to the production URL. This is correct and the test passes, but the empty-string-as-trigger is a non-obvious coupling. A more legible variant would set `RESEND_BASE_URL` directly to `https://api.resend.com`, making the guard's literal trigger condition explicit in the test name and body.
