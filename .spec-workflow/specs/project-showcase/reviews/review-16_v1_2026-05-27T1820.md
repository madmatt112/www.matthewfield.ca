## Summary

All four components type-check and adhere to the no-"use client", rel="noopener", caller-gated UpdatedBadge, and aria-labelledby restrictions; however ProjectCard's DOM ordering of card body elements diverges from Req 2.3's enumerated sequence, and the Card cover image is rendered as a sibling of CardContent leaving stray vertical padding above it.

## Findings

### WARNING: Card DOM order does not match Req 2.3 sequence
- **File:** /home/mcf/repo/matthew-field.ca/src/components/projects/project-card.tsx:34
- **Issue:** Req 2.3 enumerates card DOM order as cover, title (h3), body copy (summary), publication date, status badge, featured badge. ProjectCard renders title, date, status+featured badges, then summary — summary appears AFTER badges instead of immediately after the title, and date appears before badges instead of after them per the listed sequence.
- **Task Requirement:** 2.3

### WARNING [hygiene]: Cover image rendered outside CardContent leaves Card's py-6 padding above the image
- **File:** /home/mcf/repo/matthew-field.ca/src/components/projects/project-card.tsx:18
- **Issue:** shadcn Card applies py-6, intended for content padding. The cover-image div is a direct child of Card alongside CardContent, so the Card's top padding produces a visible empty band above the cover. Either pull the image into CardHeader/CardContent with appropriate negative margin, or remove Card's vertical padding via className. The leverage list explicitly mentions CardHeader, which appears unused.

### INFO: Featured badge inlined rather than componentized
- **File:** /home/mcf/repo/matthew-field.ca/src/components/projects/project-card.tsx:46
- **Issue:** The 'Featured' pill is rendered inline in ProjectCard rather than as a small reusable component. Not strictly required by the task (only StatusBadge/UpdatedBadge/LinkRail/ProjectCard are listed), but a FeaturedBadge would mirror the StatusBadge pattern and simplify any future Req 2.7 accent-treatment changes.
- **Task Requirement:** 2.7

### INFO: Anchor overlays the card rather than wrapping it
- **File:** /home/mcf/repo/matthew-field.ca/src/components/projects/project-card.tsx:57
- **Issue:** Req 2.6 and Req 2.3 describe the card as 'wrapped in a single anchor'. The implementation uses an absolute-positioned <Link> overlay (className='absolute inset-0') rather than a wrapping element. The accessible-name scoping via aria-labelledby is correct, and the overlay is a common idiom that still produces a single anchor — but it is not literally wrapping, so a reviewer focused on Req 2.6 wording may flag this.
- **Task Requirement:** 2.6

### INFO [hygiene]: eager prop is required rather than optional with a default
- **File:** /home/mcf/repo/matthew-field.ca/src/components/projects/project-card.tsx:14
- **Issue:** ProjectCardProps requires `eager: boolean` rather than defaulting (e.g. `eager = false`). Every caller must pass it explicitly, including below-the-fold cards that just want the default lazy behavior. Minor ergonomic friction; trivial to fix with a default parameter.
