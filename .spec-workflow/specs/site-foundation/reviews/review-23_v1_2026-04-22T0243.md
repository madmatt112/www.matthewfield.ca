## Findings

### INFO: Playground index path deviates from literal prompt (correct fix)
- **File:** src/app/(playground)/playground/page.tsx
- **Issue:** The task prompt says to create the playground index at src/app/(playground)/page.tsx, but the implementation placed it at src/app/(playground)/playground/page.tsx. The deviation is correct — because Next.js route groups are transparent, a (playground)/page.tsx would collide with (site)/page.tsx at the '/' route. The chosen path correctly produces the /playground URL and mirrors the existing (playground)/spike/page.tsx convention. Flagged only so reviewers are aware the literal prompt path was not followed; the implementation log documents the correction.
- **Task Requirement:** R7 AC1

### INFO: MDXContent uses `new Function` to evaluate Velite body
- **File:** src/components/shared/mdx-content.tsx:11
- **Issue:** src/components/shared/mdx-content.tsx calls `new Function(code)(runtime)` on every render to reconstruct the compiled MDX component. This is safe here because (a) the code string is build-time Velite output, not user input, (b) MDXContent is used exclusively from server components (e.g., /about) so evaluation happens at prerender time and never ships to the client, and (c) the CSP documented in tech steering permits server-time work. Two caveats worth capturing for future consumers: (1) if MDXContent is ever imported from a client component, the evaluator will fail under the documented CSP (no 'unsafe-eval' in script-src); (2) the reconstructed Component is re-created on each render, so if it is later passed into a client tree with state, React will treat it as a new component type on every render and remount children. Neither caveat affects the current task behaviour.
- **Task Requirement:** R7 AC1

### INFO: About page resolves Velite entry at module load, metadata/fallback inconsistent
- **File:** src/app/(site)/about/page.tsx:8
- **Issue:** src/app/(site)/about/page.tsx resolves `const aboutPage = pages.find(...)` at module scope. generateMetadata falls back to `'About'` if the entry is missing, while the page component calls notFound(). Result: if about.mdx were ever removed/renamed, the metadata would render for 'About' while the route would 404. Not a real risk today (Velite schema requires pages/about.mdx and the build prerenders it), but worth noting that the two branches should stay in agreement (e.g., have generateMetadata also branch on missing entry).
- **Task Requirement:** R7 AC1
