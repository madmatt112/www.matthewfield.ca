## Findings

### WARNING: Signal handler exits synchronously before child terminates
- **File:** scripts/run-pagefind-crawl.mjs:203
- **Issue:** onSigint/onSigterm call terminateNext() — which only sends SIGTERM and schedules a 5s SIGKILL — then immediately process.exit(130/143). Node exits synchronously, never awaiting the child. The next-start child is orphaned (PPID becomes 1) and may hang on the port. The success criterion 'killing the script mid-run produces a clean shutdown of next start' is not satisfied. Should await child exit (with a bounded timeout) before process.exit.
- **Task Requirement:** 12.4 / Success: clean shutdown of next start

### WARNING: wget exit code 8 treated as hard failure despite acknowledgement
- **File:** scripts/run-pagefind-crawl.mjs:158
- **Issue:** Comment at lines 153-155 explicitly acknowledges wget exits 8 on server-error responses (e.g. 404 on a hidden post URL we just enumerated) but the handler still rejects on any non-zero code. A single bad enumerated URL (typo, stale slug, prefix-strip miss) will fail the entire pipeline rather than skip the offending URL. Consider tolerating exit 8 with a warning or filtering URLs upstream.

### INFO [hygiene]: Velite slug prefix-strip assumes a 'posts/' prefix that may not exist
- **File:** scripts/run-pagefind-crawl.mjs:130
- **Issue:** buildExtraUrls() strips a leading 'posts/' from each slug (line 130). Velite's default slug generator emits the bare filename slug, not collection-prefixed, unless velite.config.ts customizes it. If slugs are already bare, the regex is a no-op (safe). If a future velite config change introduces a different prefix, hidden-post URLs will silently 404. A code comment exists but no assertion guards the assumption.

### INFO [hygiene]: Port-comment text varies across the three call sites
- **File:** scripts/run-pagefind-crawl.mjs:21
- **Issue:** Task 9 line 239 pins the verbatim comment as 'Port duplicated in package.json (start script) and lighthouserc.js — keep in sync.' The script uses that exact form (line 21). lighthouserc.js line 1 uses a similar but not identical wording, and design.md line 838 shows yet another variant ('package.json, lighthouserc.js, run-pagefind-crawl.mjs'). Script aligns with tasks.md but the three on-disk comments are not identical. Minor inconsistency; would not block.
