## Findings

### INFO: h3 id selector not CSS-escaped
- **File:** e2e/tests/projects-gallery.test.ts:106
- **Issue:** `card.locator(\`h3#${labelledBy}\`)` interpolates the aria-labelledby value into a CSS selector unescaped. Today this is safe because card ids are `card-title-<slug>` and Velite slugs are kebab-case (no `.`, `:`, etc.), but a future slug containing CSS-special characters would silently break the selector rather than produce a clean assertion failure. Could pre-escape via `CSS.escape` or use `[id="..."]` attribute form.
- **Task Requirement:** 2.6

### INFO [hygiene]: Card selector `ul > li` couples to DOM structure
- **File:** e2e/tests/projects-gallery.test.ts:54
- **Issue:** Uses positional `ul > li` rather than a data-testid or role-based locator. If the gallery markup changes (e.g. a wrapper list is added), all assertions silently target the wrong nodes. Acceptable for now since the markup is owned in-repo; flag for follow-up if the gallery component is refactored.
