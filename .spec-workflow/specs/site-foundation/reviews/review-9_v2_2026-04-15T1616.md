## Findings

### WARNING: components.json style changed from base-nova to new-york outside task scope
- **File:** components.json:3
- **Issue:** The task prompt says to install components using the existing components.json from task 8. Instead, components.json was modified to change the style from 'base-nova' to 'new-york', then all components were reinstalled. The implementation summary attributes this to review v1 feedback about R11 AC6 compliance. While the reasoning is sound (new-york style uses Radix primitives as required by the steering doc), this is a configuration change that goes beyond 'install components' and should have been tracked as a separate remediation or explicitly added to the task scope.
- **Task Requirement:** R11 AC6

### INFO: radix-ui umbrella package vs individual @radix-ui/* packages
- **File:** package.json:23
- **Issue:** The tech steering Decision Log #5 says 'Radix UI primitives remain npm dependencies (typically 5-15 @radix-ui/* packages)'. The implementation uses the single 'radix-ui' umbrella package (v1.4.3) which re-exports individual primitives. This is the modern approach generated by the current shadcn CLI and functionally equivalent, but it diverges from the steering doc's stated expectation. The steering doc should be updated to reflect this if the umbrella package is the intended path forward.
- **Task Requirement:** R11 AC6

### INFO [hygiene]: PopoverTitle declares h2 props but renders a div
- **File:** src/components/ui/popover.tsx:58
- **Issue:** PopoverTitle accepts React.ComponentProps<'h2'> but renders a <div> element. While div accepts all the same HTML attributes in practice, the type signature is misleading — callers might expect an h2 to be rendered for semantic/accessibility purposes. This is shadcn CLI-generated code, so it's an upstream issue, but worth noting since these components are owned source code per the steering doc.

### INFO [hygiene]: Dialog component has cross-dependency on Button
- **File:** src/components/ui/dialog.tsx:8
- **Issue:** dialog.tsx imports Button from @/components/ui/button, creating an internal dependency between UI components. This is standard shadcn new-york style behavior (the DialogFooter uses Button for its close button), but it means Button cannot be removed or significantly restructured without updating Dialog. No action needed — just documenting the coupling for future reference.
