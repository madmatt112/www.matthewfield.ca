# Implementation Log: Task 19

**Summary:** Implemented <SiteSearch /> client component (Radix Dialog + lazy Pagefind UI) and mounted its trigger in the site header. The trigger is a <button type="button"> with data-search-trigger (NEVER an <a href="#">), rightmost before the theme toggle, icon-only on <sm and label + ⌘K kbd on ≥sm, min-h-11 min-w-11. State machine: closed → opening → ready → unavailable. On first open, parallel dynamic imports of /pagefind/pagefind.js and @pagefind/default-ui are awaited via Promise.all inside a single try/catch — any rejection (failure modes a/b/d) collapses to the same observable unavailable UX containing a "Search is temporarily unavailable" body, a literal <a href="/blog">blog index</a> link, and an aria-live polite "Search index could not be loaded." sr-only announcement. PagefindUI is constructed with element=mountRef, bundlePath='/pagefind/', showImages:false, excerptLength:30, and a processResult predicate that keeps only URLs starting with /blog/ excluding /blog/ itself (Req 1.13). Loading state renders "Loading search…". Global keydown listener: `/` opens unless target is INPUT/TEXTAREA/contentEditable, dialog already open, or any modifier held; Cmd/Ctrl+K always opens. Click delegation on the dialog body closes the dialog when an a[href] is clicked (Req 1.11). A <noscript><style>[data-search-trigger]{display:none}</style></noscript> block ships inline alongside the trigger so JS-off visitors don't see a non-functional control. Added a small src/types/pagefind.d.ts module declaration so @pagefind/default-ui typechecks without a published @types package.
