## Summary

Implementation meets most R4 ACs and restrictions (semantic header/main/footer, ThemeToggle visible at all breakpoints, hamburger ARIA attributes, active-link state via usePathname, Sheet open/close). However, the desktop primary navigation is rendered as a bare <ul> with no surrounding <nav> landmark, partially violating R4 AC5 and the task's explicit 'Use semantic HTML (header, nav, main, footer)' instruction. Mobile header element order and a missing SheetDescription are minor issues.

## Findings

### WARNING: Desktop primary navigation lacks <nav> landmark
- **File:** src/components/layout/nav.tsx:24
- **Issue:** In src/components/layout/nav.tsx, the desktop navigation is rendered as <ul className="hidden ... lg:flex"> with no surrounding <nav> element. Only the mobile Sheet branch (line 60) wraps its list in <nav aria-label="Mobile">, and the SheetContent is portaled into document.body outside <header>. R4 AC5 requires semantic HTML elements including <nav>, and the task prompt explicitly instructs 'Use semantic HTML (header, nav, main, footer)'. At ≥lg breakpoints the primary navigation is therefore not exposed as a navigation landmark — screen-reader users using landmark navigation will not find the site nav. Either wrap the entire Nav output in a <nav aria-label="Primary"> (inside the component or around it in header.tsx), or convert the top-level <ul> to be a child of a <nav>.
- **Task Requirement:** R4 AC5

### INFO: Mobile header element order differs from spec
- **File:** src/components/layout/header.tsx:14
- **Issue:** The task prompt states 'Mobile header shows: site title, ThemeToggle, hamburger button' — listing ThemeToggle before the hamburger. In src/components/layout/header.tsx (lines 14-17), the DOM order inside the right-hand flex group is <Nav /> (renders the hamburger on mobile) followed by <ThemeToggle />, producing a visible order of title → hamburger → ThemeToggle. This is a visual/DOM-order deviation from the spec. If the stated order was prescriptive, swap the two elements so ThemeToggle precedes the hamburger.
- **Task Requirement:** Task prompt (Mobile header layout)

### INFO [hygiene]: SheetContent missing description triggers Radix a11y warning
- **File:** src/components/layout/nav.tsx:56
- **Issue:** The Sheet in nav.tsx renders a SheetHeader with SheetTitle but no SheetDescription and no aria-describedby on the Dialog. Radix Dialog (which Sheet wraps) emits a dev-time console warning when Description is absent and aria-describedby is not explicitly set to undefined. Add a <SheetDescription> (optionally visually-hidden) such as 'Site navigation menu', or pass aria-describedby={undefined} to SheetContent to acknowledge its absence.
