## Context
Authoritative baseline: ran `pnpm test:e2e` on clean HEAD (92ae471) plus ONLY the minimal two-line Tailwind @source-not fix needed to make the suite build. Result: 122 passed / 47 failed / 4 skipped. Root cause for nearly all failures: console 'eval() is not supported... unsafe-eval' + __cspViolations — the NODE_ENV=test build serves dev-mode React that needs eval, blocked by CSP, so hydration never happens. Pre-existing, independent of visual-design. Consequence: visual-design cannot achieve a fully-green E2E suite here; its completion gate is judged as 'no NEW failures beyond this 47-test baseline' plus unit/build/axe. Passing-at-baseline tests visual-design must keep green: landing, projects-detail-layout (edited by Task 18). Already failing at baseline (cannot be E2E-verified here): contact-form*, slash-pages*, blog-reading-progress*, all component-preview*, blog-share/series/related/shiki/no-js, contact-csp.

## Decision Deferred
How to fix the E2E harness so interactive tests actually validate behavior: scripts/run-e2e.mjs builds with NODE_ENV=test and serves via next start, producing a development React bundle that requires unsafe-eval; the production CSP forbids it, so React never hydrates. ~47/173 tests fail on clean HEAD as a result. Either build the E2E target in production mode, allow unsafe-eval in the test CSP, or otherwise align the test build with the CSP.
