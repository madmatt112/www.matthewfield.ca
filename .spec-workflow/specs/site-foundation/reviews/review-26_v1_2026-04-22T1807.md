## Findings

### INFO: Desktop nav click test does not verify heading text — only 'any h1 visible'
- **File:** e2e/tests/navigation.test.ts:19
- **Issue:** e2e/tests/navigation.test.ts:19 asserts `page.getByRole('heading', { level: 1 })` without a `name` predicate. The custom 404 page also renders an h1 ('Page not found'), so this assertion alone would pass on a 404 response. The task prompt says 'assert placeholder page renders with correct title (not 404)'. In practice the placeholder block (lines 27-33) enforces label-matched headings via `page.goto`, so combined coverage is adequate, but the navigation flow itself does not prove the destination is not a 404. Tightening line 19 to `{ name: item.label }` (with special-cased exemption for /playground, where the h1 is 'Playground' — already matches) would close the gap.
- **Task Requirement:** Task prompt: 'assert placeholder page renders with correct title (not 404)'

### INFO: Placeholder verification uses direct page.goto instead of clicking nav links
- **File:** e2e/tests/navigation.test.ts:29
- **Issue:** The task prompt phrases the flow as 'Navigate to each section via nav links, assert placeholder page renders with correct title'. The implementation splits this into two decoupled tests: desktop nav tests click links but only assert URL + any h1 (see previous finding), and placeholder tests use `page.goto(item.href)` (lines 29, 36) to bypass the nav. The split is a reasonable test-isolation pattern but weakens the end-to-end chain — a broken nav link that still points to a valid href would be caught only by the URL assertion in the desktop test, not by the content assertions in the placeholder block.
- **Task Requirement:** R7 AC1 / task prompt flow

### INFO: Mobile 'closes after selection' exercises only one nav link
- **File:** e2e/tests/navigation.test.ts:73
- **Issue:** e2e/tests/navigation.test.ts:73-82 clicks only 'Projects' to verify the Sheet closes. The task prompt says 'closes after selection' (singular selection is acceptable), and the underlying onClick={() => setOpen(false)} handler is shared across all links so additional iteration would be largely redundant. Flagged only as a coverage note, not a defect.
- **Task Requirement:** Task prompt: 'closes after selection'
