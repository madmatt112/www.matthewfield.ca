## Context
Discovered while running task 23's Lighthouse pass; confirmed pre-existing and unrelated to this branch (`lighthouserc.js` and `src/lib/blog.ts` are unchanged versus main). `lighthouserc.js` lists four `/blog/fixture-*` URLs, but those posts are `draft: true` and `src/lib/blog.ts:50` filters drafts out of a production build unless `BLOG_INCLUDE_DRAFTS=1` is set. A default production build therefore 404s on all four, and lhci exits 1 at URL 4 of 7 — before the assert step ever runs. The consequence is worse than a failed run: /profile's performance assertions are never evaluated at all, so the failure looks like a fixture problem rather than an unmeasured gate. Alternatives considered: amend `lighthouserc.js` to drop the fixture URLs, or have `scripts/run-lhci.mjs` set the env var itself. Both are edits to spec-visual-design/blog-owned tooling and outside task 23's scope, which was to record a run.

## Decision Deferred
Not fixed. Task 23 worked around it by building and serving with `BLOG_INCLUDE_DRAFTS=1` and recorded the workaround in `docs/profile-resume-lighthouse-runs.md`. Neither `lighthouserc.js`'s URL list nor `scripts/run-lhci.mjs` was changed.

## Revisit Criteria
Either set `BLOG_INCLUDE_DRAFTS=1` inside `scripts/run-lhci.mjs` so the invocation is self-contained, or remove the four `/blog/fixture-*` URLs from `lighthouserc.js` in favour of a real published post. Prefer the former if the fixtures are deliberately exercising the plugin pipeline.
