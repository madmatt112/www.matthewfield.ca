### WARNING: Date rendered as raw ISO string instead of using `formatPostDate` convention
- **File:** /home/mcf/repo/matthew-field.ca/src/components/blog/related-posts.tsx:20
- **Issue:** `RelatedCard` sets both `<time dateTime={post.date}>` and the visible label to the raw ISO string `post.date` (e.g. `2026-01-01`). The existing blog-core convention in `src/components/blog/post-card.tsx:13,27` uses `const { datetime, display } = formatPostDate(post.date);` so the machine-readable `datetime` attribute and the human-readable display are split. The task's _Leverage = `existing blog-core component conventions`; reimplementing date rendering with a raw string both deviates from that convention and ships an unfriendly user-facing date (`2026-01-01` instead of the formatted display). Use `formatPostDate(post.date)` and render `<time dateTime={datetime}>{display}</time>`.
- **Task Requirement:** _Leverage: existing blog-core component conventions

### WARNING: Card link uses raw `<a>` instead of `next/link` `<Link>` per blog-core convention
- **File:** /home/mcf/repo/matthew-field.ca/src/components/blog/related-posts.tsx:15
- **Issue:** `RelatedCard` renders `<a href={`/blog/${post.slug}`}>` rather than the `Link` component from `next/link`. The blog-core convention (`src/components/blog/post-card.tsx:1,20`) uses `<Link href={...}>` for in-app navigation, which preserves client-side prefetch + soft navigation and matches the focus-ring/min-height utility pattern used elsewhere. The task _Leverage = `existing blog-core component conventions`; switching to a raw anchor regresses navigation behavior and breaks the convention without justification.
- **Task Requirement:** _Leverage: existing blog-core component conventions
