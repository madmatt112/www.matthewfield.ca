## Context
Discovered during task 22 implementation. profile-resume is the only spec of ten whose documents are untracked in git (`git ls-files .spec-workflow/specs/` lists the other nine). The docs are not gitignored — they were simply never staged. Alternatives considered: (a) stage only this spec's directory so the verifiers run for real, after a content scan for phone numbers, personal email, and uncurated resume text; (b) pause for the user to read the docs before staging; (c) leave untracked and document the gap. The user chose (c). Rationale: this repository is PUBLIC and a personal resume was previously published to it by a blanket `git add -A`, requiring a history rewrite. profile-resume's documents discuss curated employment history specifically, so they are the highest-risk category of spec doc in this repo. Neither verifier is wired into CI, so the practical loss is limited to developer-run coverage rather than an enforced gate.

## Decision Deferred
Not committing `.spec-workflow/specs/profile-resume/` to git, unlike the nine other specs which are all tracked. Consequence: `scripts/verify-requirements-coverage.mjs` and `scripts/verify-task-dependencies.mjs` — extended to cover profile-resume in task 22 — print `SKIPPED` for this spec in the worktree and anywhere the docs are absent. Their clean run against profile-resume (45/45 acceptance criteria cited, 0 orphans, 0 dangling refs, no cycles) was obtained by running them against temporary copies of the live docs from the main checkout, then removing the copies.

## Revisit Criteria
Before either verifier is promoted to a CI gate, or before any future spec's documents are committed, decide explicitly whether profile-resume's documents join them. Do not resolve this by staging the directory without a content review against the R3 curation checklist in `docs/experience-authoring.md`.
