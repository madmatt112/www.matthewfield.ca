### INFO [hygiene]: Honeypot DOM assignment is safe because the input is uncontrolled
- **File:** e2e/tests/contact-form.test.ts:157
- **Issue:** The honeypot test sets `input[name="url_secondary"]`.value via page.evaluate (line 157-162). This bypasses React's synthetic event system, which would normally make controlled-input value assignments invisible to the component. Verified via src/components/shared/contact-form.tsx:130 — `url_secondary` is read via `honeypotRef.current?.value` (uncontrolled ref), so the raw DOM value is exactly what gets submitted. The implementation is correct, but it depends on the form keeping the honeypot uncontrolled. If a future refactor controls the input via React state, this test would silently start passing for the wrong reason (value reverts to '' before submit -> mock records 0 calls regardless of honeypot logic). Worth a comment in the test for future maintainers; not blocking.
