## Context
On-site fits the "site is the front door" decision from research/newsletter-buttondown-brief.md. But essays are already canonical as blog posts on this site, so an archive listing the same essays would duplicate /blog rather than add anything — the front-door argument may already be satisfied without an archive. Building it before settling that risks a surface that exists only because the brief listed it. Buttondown's own archive pages support full modern CSS including oklch, so the hosted option needs no token port and is nearly free if chosen.

## Decision Deferred
Whether to build an on-site "past issues" archive at all (requirement 7). The brief poses on-site (fed by the Buttondown API) versus Buttondown-hosted with ported CSS.

## Revisit Criteria
An email-only issue is published, OR the owner decides the newsletter carries content the blog does not.
