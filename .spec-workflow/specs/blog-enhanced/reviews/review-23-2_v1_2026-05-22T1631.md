## Findings

### INFO: GH_TOKEN/EVENT_NAME/PR_NUMBER/REF env wired on wrong step
- **File:** .github/workflows/ci.yml:149
- **Issue:** The Vercel deploy step's `env:` block exposes GH_TOKEN, EVENT_NAME, PR_NUMBER, and REF, but the deploy `run:` only uses VERCEL_TOKEN/VERCEL_ORG_ID/VERCEL_PROJECT_ID. The four extra vars are consumed by scripts/warn-no-pagefind.mjs, which is invoked by the `Warn deploying without Pagefind` step added in Task 23.3, not by `Vercel deploy (Build 2)`. Wiring them here is forward-compatible scaffolding but is misleading — Task 23.3 should wire those on the warn step itself.
- **Task Requirement:** Env wiring per the design YAML block

### INFO [hygiene]: DEPLOY_URL capture assumes vercel CLI emits only the URL to stdout
- **File:** .github/workflows/ci.yml:147
- **Issue:** `DEPLOY_URL=$(pnpm exec vercel deploy --prebuilt ...)` captures all stdout. If a future vercel CLI version (or pnpm exec wrapper) emits progress lines or warnings to stdout in addition to the URL, deploy_url will contain extra noise and downstream consumers (Task 23.3 warn step DEPLOY_URL) will receive a malformed value. Vercel CLI today emits only the URL to stdout with diagnostics to stderr, so this is currently safe — flagging for awareness when bumping the CLI pin.
