## Findings

### WARNING: Case 13b restore via `git reset --soft HEAD~1` is incorrect for an --amend
- **File:** src/lib/projects.test.ts:593
- **Issue:** `git commit --amend` modifies the current commit in place; resetting to HEAD~1 then unstaging would discard the original commit's changes rather than restore it. Correct restoration after an amend is `git reset --soft ORIG_HEAD` (which git sets at amend time). The errors are swallowed by the catch-all in finally, so a failed mutation leaves the repo in a corrupted state silently. Path is opt-in (PROJECTS_TEST_GIT_MUTATION=1) so impact is bounded, but the case will not reliably self-restore in CI when it eventually runs.
- **Task Requirement:** 1.5 (Case 13b restore pattern)

### WARNING: Case 10 does not use a scoped `vi.mock` per spec restriction
- **File:** src/lib/projects.test.ts:628
- **Issue:** Spec restriction: "Empty-collection in a separate `describe` so `vi.mock` is scoped" and the case text calls for `vi.mock("#site/content", () => ({ projects: [] }))` in a separate describe. The implementation reuses the file-scoped hoisted mock and sets `mockProjects.value = []` in a separate describe. Semantically equivalent given Vitest's mock hoisting, but a literal-restriction deviation that the code comment explicitly acknowledges.
- **Task Requirement:** 1.8 (Case 10)
