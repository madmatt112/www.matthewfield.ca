### INFO [hygiene]: allowlist filter throws on a partial custom allowlist
- **File:** src/lib/build/check-content-chokepoint.ts:437
- **Issue:** The final filter does `!allowlist[finding.symbol].includes(relPath)`. The default allowlist is complete (both symbols), so production use is safe and typecheck passes (type is Record<ContentSymbol,...>). But a caller passing a runtime object missing one symbol key would hit `undefined.includes` and throw. Low impact for a single-author repo with a complete default; a defensive `(allowlist[finding.symbol] ?? [])` would harden it.
