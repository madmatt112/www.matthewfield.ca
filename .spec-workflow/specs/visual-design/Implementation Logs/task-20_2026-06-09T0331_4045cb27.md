# Implementation Log: Task 20

**Summary:** Task 20 — Added a lightweight Vitest active-role↔token presence test at src/styles/tokens.test.ts. It reads tokens.css and globals.css as text, extracts the :root, .dark, and `@theme inline` blocks via brace-matching, and asserts for each active role (brand, brand-foreground, brand-visited, success/-foreground, warning/-foreground, info/-foreground, destructive) that --<role> exists in BOTH :root and .dark of tokens.css and that --color-<role> is mapped in @theme of globals.css. destructive-foreground is treated as optional: enforced only if present in :root (then it must also be in .dark and @theme). Failures carry role-named messages so a role added to the design but missing from tokens/@theme fails loudly. 31 tests pass; pnpm typecheck passes. Stand-in for the deferred CI active-role↔token check; scope intentionally limited to presence/mapping, no value/contrast checks.
