## Context
Extracting it means editing src/app/api/contact/route.ts, which sits under the repo's paired-merge CI guards that force coupled files to change all-or-none. Doing that inside a newsletter feature would widen the diff well beyond the feature and drag unrelated files into review. Copying was chosen as the smaller harm, with the duplication recorded rather than hidden. This is a security control, so two copies drifting is a real risk, not a style concern.

## Decision Deferred
Whether to extract the isAcceptedHost / originAllowed CSRF pair into a shared module. It is currently copied verbatim into src/app/api/newsletter/route.ts from src/app/api/contact/route.ts.

## Revisit Criteria
A third consumer appears, OR api/contact is being modified anyway, OR the paired-merge guard configuration changes so the extraction no longer forces coupled edits.
