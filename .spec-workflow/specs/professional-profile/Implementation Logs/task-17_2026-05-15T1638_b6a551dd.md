# Implementation Log: Task 17

**Summary:** Implemented `<ContactForm />` core at `src/components/shared/contact-form.tsx`. Top-level `"use client"`. Exports `ContactForm(props: { source?: 'profile' | 'contact' })`.

State machine per design: single `useState<FormState>` discriminated union (`idle | submitting | success | validation-error | server-error`); separate `useState<Fields>` for `{name, email, message}`; separate `useState<number>` for `attemptId` incremented on every submit-handler entry. The `attemptId` value is intentionally read via `void attemptId` to make it visible to the closure surface that tasks 17.1–17.3 will hook with a `useEffect` keyed on `[attemptId, state.kind]`.

Submit guarding: `aria-disabled={isSubmitting}` on the submit `<Button>` (NOT native `disabled`), plus an `if (state.kind === 'submitting') return;` early-return at the top of `handleSubmit`. Button label flips between static text "Send" / "Sending…" — no spinner animation.

DOM structure: `<form noValidate>` with a responsive grid (`grid grid-cols-1 sm:grid-cols-2`) putting `name` and `email` side-by-side at the `sm:` breakpoint and stacking below; `message` lives in its own full-width row. Each field has `<Label htmlFor>` + `<Input>`/`<Textarea>` with native `required`, no `aria-required`. Per-field `<span aria-live="polite">` linked via `aria-describedby` (only when an error is present for that field). Honeypot is a `<div style={{display:'none'}} aria-hidden="true">` wrapping `<input name="url_secondary" tabIndex={-1} autoComplete="off" />` read via `honeypotRef`. Validation summary is a top-level `role="alert"` div. The success and server-error UIs replace the form and render in a `role="status" tabIndex={-1}` container; the success heading is an `<h2 tabIndex={-1}>`. The whole region is wrapped in `<div className="min-h-[28rem]">` for layout-shift prevention — the value was sized to comfortably cover the success-state render envelope.

44×44 tap targets: submit `<Button>` and the recovery "Try again" button both carry `min-h-11 min-w-11`; each Input adds `min-h-11`; the Textarea uses `min-h-44`.

Submission pipeline: builds JSON `{ name, email, message, url_secondary, source, testId? }`; `testId` is included only if `window.__TEST_ID` is a string (E2E hook; never sourced from props/forms). `AbortController` with a 12-second ceiling; on fetch reject/abort → `server-error` with `status: 'network'`. The fetch is wrapped in a try/catch/finally so the timer is always cleared.

Status-code mapping (Req 4.4): `200 → success` (fields cleared); `400 → validation-error` only when body has a `errors` object with field-shaped keys, otherwise falls through to `server-error` with `status: 'unknown'` (covers the 400 `{error:'Malformed request.'}` shape); `429 / 502 / 503 / 504 → server-error` with the literal status; any other status → `server-error` with `status: 'unknown'`. The 503 branch parses `response.headers.get('Retry-After')` as an integer ≥ 0 into `retryAfterSeconds`. The 429 branch does not read the body (Vercel HTML body is fine).

Server-error UI: heading + descriptive body per `status`, optional "Try again in about N seconds" hint when `retryAfterSeconds` is set on a 503, a "Try again" Button that resets state to `idle` (form values preserved because `fields` state is untouched), and an inline `<a href={siteConfig.links.linkedin} target="_blank" rel="noopener external">Or reach out on LinkedIn</a>`. Copy varies per `status` (429/502/503/504/network/unknown).

Field-error self-heal: editing a field while in `validation-error` state clears that field's error via `clearFieldError`. Server-error is only cleared by clicking "Try again" (matches design §Form-State Machine "edit clears per-field error only" rule).

Window typing: added a `declare global { interface Window { __TEST_ID?: string } }` at file end so `window.__TEST_ID` typechecks.
