## Findings

### INFO: Assertion (b) literal tightened vs. spec text
- **File:** src/lib/velite-safe-body-html.test.ts:52
- **Issue:** Spec text for (b) says assert `body` contains `data-copy-source=`. Implementation asserts `data-copy-source` (no `=`) because Velite's `s.mdx()` emits compiled JSX as a JS string where the attribute appears as the object-key form `"data-copy-source":"..."`. Rationale is documented in the test file. Spec intent (attribute survives in the body artifact) is preserved; surfacing as info so reviewers note the literal divergence.
- **Task Requirement:** 9.10

### INFO [hygiene]: Fixture slug not added to KNOWN_FIXTURE_SLUGS roster
- **File:** content/posts/fixture-unicode-code.mdx
- **Issue:** `fixture-unicode-code` is gated only by `draft: true` (plus the suite's `BLOG_INCLUDE_DRAFTS=1` override) and is not registered in `src/lib/build/derive-post-slug.mjs`'s `KNOWN_FIXTURE_SLUGS` set. Because `isHiddenFromLists` checks that set exactly (no `fixture-*` prefix match despite the doc-comment claim), the fixture would appear in visible list contexts if anything else ever sets `BLOG_INCLUDE_DRAFTS=1` outside this test. Test passes today because the feed assertion expects the fixture to be visible, but the divergence between the doc-comment and the implementation is a latent footgun. Consider either adding the slug to the roster (and updating the test's (c) assertion to not depend on visibility) or treating this as known/acceptable.
- **Task Requirement:** 11.4
