#### Integration
- **Description:** Replaced the `--shiki-active` shim variable approach with direct binding of `color`/`background-color` to per-theme variables on the consumer selector. Root cause: the previous shim resolved `--shiki-active: var(--shiki-light)` at `:root`, but `--shiki-light` is set inline on each span — at `:root` it has no value, so `--shiki-active` computed empty and spans fell through to inherited prose colors (lab(2.75 0 0), near-black, identical in light + dark). The fix binds `color: var(--shiki-light)` directly on the consumer rule `[data-rehype-pretty-code-figure] span` (plus `.dark` and `:root:not(.light):not(.dark) @media` variants for the cascade), where the inline `--shiki-light` IS in scope. Includes `.prose [data-...]` variants to outrank Tailwind typography's `.prose code` color rule. Patch diagnosed by capturing `getComputedStyle(span).color` returning `lab(2.75381 0 0)` regardless of theme; post-patch returns `rgb(36,41,46)` light + `rgb(225,228,232)` dark.
