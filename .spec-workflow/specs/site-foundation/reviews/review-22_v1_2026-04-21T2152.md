## Summary

Implementation satisfies R6 AC1–AC6 and R10 AC3, with a server-component landing page, data-driven hero grid, and a single-focusable HeroCard. One info-level accessibility concern: hero card titles render as divs rather than semantic headings, and the grid section has no visible heading.

## Findings

### INFO: HeroCard title is not a semantic heading
- **File:** src/components/shared/hero-card.tsx:19
- **Issue:** HeroCard uses shadcn's CardTitle, which renders as a <div> (see src/components/ui/card.tsx:31-39), not an <h2>/<h3>. The page also omits any visible heading above the 6-card grid. For a landing page whose purpose is to orient visitors across six major sections, heading semantics would aid assistive tech navigation and document outline. The Link wrapping gives each card an accessible name via its text content, so this is not a hard R6/WCAG failure — but a heading upgrade (either by passing `asChild`-style override or adding an <h2>/<h3> inside each card) would better match 'approachable and human' + WCAG 2.1 AA usability goals cited in the spec.
- **Task Requirement:** R6 AC2
