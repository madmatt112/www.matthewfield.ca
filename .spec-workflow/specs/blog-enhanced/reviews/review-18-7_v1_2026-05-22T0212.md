## Findings

### WARNING: CSS ::before pseudo-content may duplicate accessible name with aria-label
- **File:** /home/mcf/repo/matthew-field.ca/src/styles/blog/copy-button.css:40
- **Issue:** The button carries aria-label='Copy code to clipboard' AND a CSS ::before with content:'Copy' / 'Copied' / 'Failed'. Modern Chromium/WebKit accessibility trees expose pseudo-element generated text, so screen readers may announce both the pseudo content and the aria-label ('Copy. Copy code to clipboard'), or the aria-label may override the pseudo (the latter is the spec, but Chromium has historically merged them). Consider either (a) marking the pseudo aria-hidden equivalent by giving the button explicit child text and dropping ::before, or (b) accepting the redundancy and documenting. Either is fine; flagging for awareness.
- **Task Requirement:** 9.5

### WARNING: Theme-parity assertion may be fragile under next-themes class-based switching
- **File:** /home/mcf/repo/matthew-field.ca/e2e/tests/component-preview/copy-button.test.ts:64
- **Issue:** The Playwright smoke proves theme parity by comparing computed color after page.emulateMedia({colorScheme:'light'|'dark'}). The theme-provider uses next-themes default (class attribute toggling). emulateMedia flips prefers-color-scheme, which next-themes only honors when theme=system and enableSystem=true; the .dark class is applied client-side after hydration. The test calls goto() separately for each theme so hydration re-evaluates, which should work — but if the provider ever changes to defaultTheme='light' or storageKey carries a sticky value across navigations, the assertion silently passes by reading the same color twice. Consider explicitly toggling via the theme provider's API or asserting on the html.dark class before reading color, to make the proof robust.
- **Task Requirement:** 9.1

### INFO [hygiene]: announceCopyStatus shared timer can be cancelled by other buttons mid-announcement
- **File:** /home/mcf/repo/matthew-field.ca/src/components/blog/clipboard.ts:19
- **Issue:** clipboard.ts holds a single module-level clearTimer for the #copy-status region. If two buttons are clicked in rapid succession (rare on a single article but possible), the second click's announceCopyStatus call clears the first timer and replaces the text, which is desirable. Noted only because the per-button state machine in CopyButton tracks per-button reset timers independently, so global vs per-button timer semantics diverge slightly — acceptable, but worth noting.
