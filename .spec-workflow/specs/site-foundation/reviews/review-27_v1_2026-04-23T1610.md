## Summary

Test covers all 6 hero-card hrefs with accessible selectors and region scoping, but relies on the config for cardinality (no explicit count assertion) and uses an unescaped RegExp that is brittle to future title changes.

## Findings

### WARNING: No explicit count assertion for 6 hero cards
- **File:** e2e/tests/landing.test.ts:11
- **Issue:** The task prompt and R6 AC2 specify that 'all 6 hero cards are visible'. The 'all hero cards render' test iterates over siteConfig.heroCards and asserts each is visible, but never asserts the set size is 6. If siteConfig.heroCards drifts to 5 or 7 entries (regression), the test silently passes while covering the wrong number of cards. Add an explicit cardinality assertion — e.g. `await expect(sections.getByRole('link')).toHaveCount(6)` — so the '6' in the spec is enforced, not implied.
- **Task Requirement:** R6 AC2

### WARNING: Unescaped RegExp for accessible-name matching is fragile
- **File:** e2e/tests/landing.test.ts:16
- **Issue:** `new RegExp(card.title)` passes card.title straight into a regex constructor with no escaping. Current titles (Professional Profile, Projects, Contributions, Blog, Resources, Playground) contain no regex metacharacters, so it happens to work today — but any future title with `.`, `(`, `)`, `+`, `*`, `?`, `[`, `]`, `|`, `\`, `{`, `}` would either produce a malformed pattern or match unintended substrings. The sibling file e2e/tests/navigation.test.ts uses plain strings (`getByRole('link', { name: item.label })`) which Playwright treats as substring-match on the accessible name and avoids the escaping problem entirely. Prefer the plain-string form for parity and safety. Also note that the link's accessible name already includes both the h3 title and the CardDescription, so substring matching on the title alone is sufficient — the RegExp buys nothing that a plain string doesn't.
- **Task Requirement:** R6 AC2

### INFO: Relative import path instead of @/ alias
- **File:** e2e/tests/landing.test.ts:3
- **Issue:** Test imports siteConfig via `../../src/config/site` rather than the project's `@/*` path alias used throughout src/. Consistent with the sibling e2e/tests/navigation.test.ts, so this is a project-wide e2e convention rather than a regression introduced by this task — but worth flagging: the e2e suite has opted out of the `@/` alias without documenting why (likely because no ts-path resolver is configured for the Playwright test runner), and a follow-up to align e2e imports with the alias would improve consistency.
