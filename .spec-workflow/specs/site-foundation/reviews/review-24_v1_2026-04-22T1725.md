## Summary

Task 24 meets R8 AC1 and AC2 — the 404 page renders with a heading, description, Return home link, and manually-included Header/Footer to satisfy the 'site layout shell' restriction at a location where route-group layouts do not apply. Findings are non-critical: layout-shell duplication creates a drift risk, the page ships no 404-specific metadata, and the implementation log names a theme token that the code does not actually use.

## Findings

### WARNING: Site shell duplicated instead of extracted — drift hazard
- **File:** src/app/not-found.tsx:8
- **Issue:** src/app/not-found.tsx hard-codes the exact top-level structure already defined in src/app/(site)/layout.tsx — outer `<div className="flex min-h-dvh flex-col">`, `<Header />`, `<main className="flex-1">`, `<Footer />`. The two shells are now two independent sources of truth. Any future change to (site)/layout.tsx (background color, skip link, padding, error boundary, analytics wrapper, etc.) will silently fail to propagate to the 404 page, producing a visibly inconsistent experience on the very page users already see when something is wrong. The correct fix is to extract a `<SiteShell>` component consumed by both (site)/layout.tsx and not-found.tsx. This is a genuine maintenance concern, not a style preference — the implementer even recognized the constraint in the log ("a root-level not-found.tsx does not inherit route-group layouts") but chose duplication over extraction. Acknowledged acceptable for this task, but should be addressed before additional layout chrome is added in downstream specs.
- **Task Requirement:** R8 AC2

### INFO: No 404-specific page metadata
- **File:** src/app/not-found.tsx:6
- **Issue:** The 404 page does not export `metadata` (or `generateMetadata`). With the root layout's `title.default` being `siteConfig.name` ("Matthew Field") and `title.template` requiring a page-supplied string to activate, navigating to a nonexistent URL shows a browser tab labelled simply "Matthew Field" — indistinguishable from the landing page. A short `export const metadata = { title: "Page not found" }` would use the template to produce "Page not found | matthew-field.ca", which is both clearer for users and more honest for anything scraping tab titles. R8 does not require this, but it is a conspicuous polish gap for a page whose entire purpose is orientation during a navigation failure. Also note that other placeholder pages in this spec (task 23) export metadata with `robots: { index: false }`; the 404 does not, which is defensible (the route itself returns HTTP 404 so indexing is moot) but the inconsistency is worth a conscious decision rather than an omission.
- **Task Requirement:** R8 AC1

### INFO [hygiene]: Implementation log cites a theme token the code does not use
- **File:** .spec-workflow/specs/site-foundation/Implementation Logs/task-24_2026-04-22T1723_a28ceb57.md:3
- **Issue:** The implementation log claims styling uses "theme-variable tokens (muted-foreground, primary, border)". `muted-foreground` and `primary` are present in not-found.tsx (via `text-muted-foreground` and `text-primary`), but no `border-*` utility appears anywhere in the file — no `border`, `border-border`, `border-b`, etc. Small log-vs-code drift; does not affect the rendered output but the log is the artifact reviewers and future-you read to understand the change, so it should describe what was actually built.

Task 26 will add E2E coverage, so this is informational, but the current task closed without a concrete runtime confirmation beyond framework semantics.
