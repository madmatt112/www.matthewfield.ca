[spec-workflow-mcp](https://github.com/madmatt112/spec-workflow-mcp) is my fork of Pimzino's spec-driven-development MCP server, with adversarial review, a required decomposition phase, a deferred-decisions tracker, and fresh-context task review added on top. [v5.1.0 is out.](https://github.com/madmatt112/spec-workflow-mcp/releases/tag/v5.1.0)

## The bug worth telling you about

INDEX.md was always a decent inventory: three tables of which specs exist and what state each one is in. The choice of what to actually work on next was left to you, or to your agent.

The rule behind that only ever read two of the three tables. Once every spec named in `decomposition.md` was complete, it called the roadmap finished and never reached the "Other specs" table below, which is where every spec added after decomposition lives. I had a project with three specs in flight, all three of them in that table, one of them open on screen at the time, and INDEX.md still told me there was nothing left to do.

## What 5.1.0 does about it

INDEX.md now opens with a `## Next` section naming one spec and the reason for it, mirrored in the `spec-index` tool result as `routing` so an agent branches on a field instead of re-deriving the rule from prose.

It also admits when it doesn't know. Two half-built specs with no declared order between them gets you both candidates and a stop, not a confident guess. And when everything really is done, it says every spec _on disk_ is complete rather than claiming the roadmap is finished, because `decomposition.md` routinely names the next spec before its directory exists. That gap is the whole bug.

Two smaller fixes came along for the ride. A spec sitting on its last task read as not-yet-implementing, which could leave the document loop and the implementation loop each waiting on the other after an interrupted run. And open checkboxes the task parser can't read now raise a warning instead of quietly counting for nothing.

## Upgrading

Run the `spec-index` tool once with `action: generate` in each project. INDEX.md is written to disk rather than computed when read, so your existing file keeps its old shape until something rewrites it.
