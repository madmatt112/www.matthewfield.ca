### WARNING [hygiene]: Timeout mode can block graceful shutdown via held-open socket
- **File:** e2e/fixtures/mock-resend.mjs:60
- **Issue:** In `timeout` mode /emails returns without ending the response, holding the connection open. The SIGTERM handler calls server.close(cb) which waits for all connections to drain, so cb never fires and the mock won't exit gracefully if a timeout mode is active at teardown without a /__reset. run-e2e.mjs only sends SIGTERM (no SIGKILL fallback), so a wedged mock relies on OS process kill. Consider server.closeAllConnections() in shutdown(), or a bounded server-side timer that ends the hung response. No timer/socket is leaked during the test run itself (modes hold no setTimeout).
