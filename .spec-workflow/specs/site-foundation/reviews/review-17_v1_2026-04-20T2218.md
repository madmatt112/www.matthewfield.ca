## Findings

### INFO: Icon sizing may be overridden by Button's descendant-SVG rule
- **File:** src/components/layout/theme-toggle.tsx:21
- **Issue:** Sun/Moon icons use `h-[1.2rem] w-[1.2rem]`. Button (src/components/ui/button.tsx:8) applies `[&_svg:not([class*='size-'])]:size-4` to descendant SVGs that lack a `size-*` class. The icons' classes use `h-*`/`w-*` (not `size-*`), so the `:not([class*='size-'])` negation matches and the descendant rule applies. That compiled selector (`.button-class svg:not([class*='size-'])`, specificity ~0,2,1) beats the single-class `h-[1.2rem]` / `w-[1.2rem]` utilities (specificity 0,1,0), so icons may actually render at 1rem rather than the intended 1.2rem. This matches shadcn's documented toggle pattern and may be visually acceptable, but the CSS author intent (1.2rem) is not necessarily realized. Recommend visual verification in a browser or switching to `size-5` (1.25rem) to bypass the negation and avoid the specificity conflict.
- **Task Requirement:** Task prompt: sun/moon icons from lucide-react as trigger

### INFO: DropdownMenuItem uses onClick instead of Radix-idiomatic onSelect
- **File:** src/components/layout/theme-toggle.tsx:26
- **Issue:** Radix DropdownMenu.Item exposes `onSelect` as the canonical handler that fires on both pointer click and keyboard Enter/Space; `onClick` also works because Radix synthesizes a click event on keyboard activation, so keyboard accessibility is preserved. This is a minor convention deviation, not a functional defect — keyboard selection still changes the theme. Noting in case future refactors want consistency with the Radix documentation and other menu handlers in the codebase.
- **Task Requirement:** Must be keyboard-accessible
