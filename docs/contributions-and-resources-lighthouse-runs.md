# Lighthouse runs — contributions-and-resources

Tracks Lighthouse re-verification cadence for the contributions-and-resources
feature (Req NFR-Performance). The cadence script
`scripts/check-contributions-resources-lighthouse-cadence.mjs` reads the most
recent run entry's `- Entries at run time (contributions + resources): N` line.

Pin: when `(current_count - last_count) >= 10`, the CI cadence step fires red
and a new run entry MUST be added below before the build can go green again.
"current_count" is `contributions.length + resources.length` — the combined
entry count from `.velite/contributions.json` and `.velite/resources.json`
produced by Build 2. There is no draft/fixture filtering: neither collection
has a draft flag, and the cadence tracks every published entry across both
pages.

### Reproduction

```sh
pnpm exec velite build
BLOG_INCLUDE_DRAFTS=1 pnpm build
BLOG_INCLUDE_DRAFTS=1 pnpm start            # separate shell; binds port 3013
pnpm lhci --upload.target=filesystem --upload.outputDir=./.lighthouseci/reports
```

Three things this sequence exists for, all of which produce a silently wrong
record if skipped:

- **`pnpm lhci` builds nothing and starts nothing.** `scripts/run-lhci.mjs:88`
  spawns only `pnpm exec lhci autorun`; with `collect.url` set and no
  `serve:lhci` script, Lighthouse audits whatever is already listening on
  `localhost:3013`. `velite build` alone is inert — the served bundle comes from
  the last `pnpm build`, so a stale pre-feature build yields four real-looking
  scores for a page the heatmap is not on. Before auditing, the served page was
  checked directly: `curl -s localhost:3013/contributions` returned 87,084 bytes
  containing `github-activity-heading` and 354 `contrib-heatmap__cell`
  occurrences.
- **`BLOG_INCLUDE_DRAFTS=1` on both the build and the server.** Four of the
  eight audited URLs are draft-only fixture posts that 404 otherwise, which
  aborts the collect step before any assertion runs
  (`docs/profile-resume-lighthouse-runs.md:105-125`).
- **Nothing else may hold port 3013.** The `dev` script binds it
  (`package.json:7`); auditing a Turbopack dev server with the overlay and HMR
  client attached puts Performance far below 90 — a harness artefact, not a page
  defect. Port 3013 was confirmed free before the run and released after it.

`--upload.target=filesystem` was passed because `lighthouserc.js:78-81` defaults
to `temporary-public-storage`, which publishes every report to a public Google
Cloud bucket. Reports were kept local instead, as in the precedent run.
`pnpm build:search` was **not** run, so `public/pagefind/` was absent — which is
what the byte-weight audit intends anyway, and irrelevant to `/contributions`
(zero Pagefind requests, confirmed above).
