## Findings

### INFO: Skip-if-absent gate silently passes if fixture content is removed locally
- **File:** e2e/tests/projects-draft-handling.test.ts:24
- **Issue:** The beforeAll guard only skips when `.velite/projects.json` is missing entirely. If a developer locally has a stale `.velite/projects.json` that doesn't contain `fixture-placeholder` or `fixture-published-second` (e.g., they removed the fixtures), Build-1 assertions like `toHaveCount(1)` for the draft card would fail with a generic Playwright error rather than a clear 'fixture missing' diagnostic. CI is unaffected (Task 19.5 pretest gate covers it), but local DX could be improved by sanity-checking that both fixture slugs exist in the parsed JSON during beforeAll. Optional polish — not a blocker.

### INFO [hygiene]: Hard-coded fixture slugs duplicate knowledge held in projects-gallery.test.ts
- **File:** e2e/tests/projects-draft-handling.test.ts:20
- **Issue:** `DRAFT_SLUG` and `PUBLISHED_SLUG` are hard-coded constants here, while `projects-gallery.test.ts` derives the expected set from `.velite/projects.json`. This is acceptable (the draft-handling contract pins specific fixtures by design), but if fixture slugs are ever renamed both test files must be updated in lockstep. A short comment cross-referencing `content/projects/fixture-*.mdx` would aid future maintainers. Not a correctness issue.
