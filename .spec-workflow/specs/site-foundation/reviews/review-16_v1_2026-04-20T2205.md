## Findings

### WARNING: openGraph image path is relative but metadataBase is not set and no downstream task plans to add it
- **File:** src/app/layout.tsx:22
- **Issue:** metadata.openGraph.images uses the bare path '/images/og-default.png'. Next.js resolves relative OG image URLs against `metadataBase`; when it is unset, Next.js falls back to http://localhost:3000 and emits a build-time warning — meaning production social link previews would reference localhost unless metadataBase is set before deploy. The implementation log explicitly defers this to 'task 18/20', but task 18's prompt only creates siteConfig (with a `url` field) and task 20's prompt only creates sitemap.ts and references the manual OG image file; neither prompt currently instructs the implementer to wire siteConfig.url into `metadata.metadataBase` in layout.tsx. This leaves the responsibility floating. Either (a) amend task 18 or 20's scope to explicitly set metadataBase in layout.tsx, or (b) supply an absolute URL here.
- **Task Requirement:** R10 AC1 / task prompt (openGraph image)

### WARNING: disableTransitionOnChange prop was added to ThemeProvider but is not specified by the task
- **File:** src/app/layout.tsx:43
- **Issue:** The task prompt instructs: 'wrapping next-themes ThemeProvider with attribute="class", defaultTheme="system", enableSystem'. The implementation additionally passes `disableTransitionOnChange` from layout.tsx:43 into the ThemeProvider. While this is a sensible default for next-themes usage, it is a behaviour addition beyond what the task asked for and conflicts with the user's global guidance to 'DO NOT add features I didn't request / Keep solutions simple and direct'. If kept intentionally, this decision should be justified (e.g., prevents transition flicker during theme toggle); otherwise drop it to match the prompt.
- **Task Requirement:** task prompt (ThemeProvider props)
