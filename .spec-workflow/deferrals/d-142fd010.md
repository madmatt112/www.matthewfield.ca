## Context
Task 15 review v1 flagged the uncomputed ratio as a WARNING; review v2 INFO asked for the math to be done. Computation (oklch→linear sRGB alpha-composite→WCAG luminance ratio): destructive oklch(0.704 0.191 22.216) resolves to linear sRGB (1.000, 0.127, 0.136); dark --background oklch(0.145 0 0) resolves to linear sRGB (0.003, 0.003, 0.003); 0.6·dest + 0.4·bg = (0.601, 0.077, 0.083); Y_composed = 0.189; Y_white = 1.000; contrast = (1.00 + 0.05) / (0.189 + 0.05) = 4.39:1. Light-mode destructive is separately 4.76:1 (passes AA-normal). Alternatives considered: (a) darken `--destructive` in .dark to lift composited luminance — diverges from shadcn neutral defaults and creates regeneration drift; (b) override the Button variant to `dark:bg-destructive` (drop the /60 alpha) — lifts to 2.89:1 against white, which is worse; (c) swap text-white for a token-derived foreground brighter than white (not possible — white is the luminance ceiling). No local fix improves AA-normal without diverging from upstream.

## Decision Deferred
Computed the as-rendered contrast for the dark-mode destructive Button (dark:bg-destructive/60 over --background with text-white). Result: 4.39:1. This clears AA-large (3:1) but misses AA-normal (4.5:1) by 0.11. The Button default size uses text-sm font-medium, which does not qualify as WCAG "large text" (≥18pt, or ≥14pt bold with 700+ weight), so the 4.5:1 threshold nominally applies. Accepting the deviation rather than adjusting tokens — matches shadcn upstream verbatim; overriding the destructive oklch or alpha locally would diverge from the regenerable scaffold tokens.css pins.

## Revisit Criteria
During the first accessibility audit pass, or if the destructive Button variant's dark-mode treatment changes (e.g., shadcn upstream alters `dark:bg-destructive/60`, or we override the variant).
