## Context
Discovered while implementing profile-resume task 6 (registering the experience/skills/education collections) and independently confirmed by the task-6 reviewer. `package.json`'s `build` script is `next build` alone; velite runs via `postinstall` and via vitest's globalSetup. `vercel.json` also calls `pnpm build`. Consequently a malformed content YAML file does NOT fail a local `pnpm build` — it only fails when `pnpm install` (CI, `--frozen-lockfile`) or `pnpm exec velite build` runs. Every task in this spec whose success criterion reads "fails the build" therefore has to invoke `velite build` explicitly, which is a trap for any future content spec that assumes `pnpm build` is the gate. A related sharp edge found in the same task: a collection registered in the `collections` map but NOT in `makeContentYamlLoader` does not fail at all — velite logs info-level issues, exits 0, and ships the invalid entry verbatim into `.velite/*.json`, because `defineConfig` does not set `strict: true` (see deferral d-b2055869). Options considered: (a) add `velite build` to the `build` script, (b) rely on postinstall + CI as today, (c) resolve d-b2055869 by setting `strict: true`. Deliberately not decided here — profile-resume's scope is the resume content, and changing the build script mid-spec risks the CI pipeline the spec depends on.

## Decision Deferred
Not wiring `velite build` into the `build` script, so the documented build command does not exercise content-schema validation.

## Revisit Criteria
A content-schema regression reaches a deploy, or a contributor reports that a malformed YAML file passed local `pnpm build`, or d-b2055869 comes up for decision.
